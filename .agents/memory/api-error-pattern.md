---
name: API Error handling pattern
description: How to extract error messages from ApiError thrown by customFetch hooks
---

Hooks generated by Orval throw `ApiError` (from `lib/api-client-react/src/custom-fetch.ts`) on non-2xx responses.

**Rule:** Never cast `error as { error?: string }` — that accesses a non-existent property on the Error object.

**How to apply:**
```ts
const extractErrorMsg = (error: unknown): string => {
  if (error && typeof error === "object") {
    const data = (error as { data?: { error?: string } }).data;
    if (data?.error) return data.error;
    const msg = (error as Error).message;
    if (msg) return msg;
  }
  return "알 수 없는 오류";
};
```

`ApiError.data` = parsed JSON response body (e.g. `{ error: "이미 사용 중인 사이트 이름입니다" }`)
`ApiError.message` = formatted string like "HTTP 409 Conflict: ..." (includes HTTP status)

**Why:** The generated hooks wrap fetch in customFetch which throws ApiError, not plain Error or { error: string }.
